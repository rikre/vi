# 管理配置与项目创编：三轮体验迭代

## 依据与范围

依据 DESIGN.md、docs/merge-review-20260910.md、docs/script-studio.md、docs/prompt-workbench.md 以及本地代码与测试。“相关公文”按项目产品／设计说明理解，未获得新的外部公文或飞书正文。

本轮只调整交互与异常恢复，不修改正式售价、支付渠道、企业数据权限、数据库环境或真实模型配置。已有未提交改动保留。

## 第一次：P0 保存与失败恢复

闭环：编辑 → 校验 → 锁定提交 → 成功关闭／失败保留 → 重试。

- 管理员套餐、充值档位保存期间禁用表单、阻止重复提交及关闭。
- 接口失败时保留草稿，弹窗内保留错误信息，不仅依赖短暂 toast。
- 关闭有改动的配置前要求确认。
- 修正套餐说明，明确后台保存不代表前台商品已发布。
- 组件测试使用受控 Promise 验证慢请求、重复提交、保存失败、重试及取消确认；不写真实后台数据。

## 第二次：P1 导航与创编确认

闭环：剧本编辑 → 保存版本 → 分镜提示词 → 返回剧本 → 历史恢复。

- 项目标签以 URL 为状态来源，切换写入网址；刷新、前进和后退恢复正确标签。
- 保存剧本后提供“下一步：分镜提示词”，未保存时提示先保存版本。
- 创编修改稿可展开修改前原稿，再确认应用。
- 项目 Skills／Agent 设置关闭前检查未保存改动，拒绝放弃时保留输入。
- 浏览器测试覆盖配置保存、版本恢复、下一步、刷新和历史导航。

## 第三次：P2 异常路径与回归

闭环：发现不可用 → 知道原因及影响 → 执行恢复步骤 → 重试 → 再核对数据。

- 管理后台接口不可用时保留六个模块的导航和当前模块说明。
- 显示部署恢复步骤；数据不可用时不提供新建／编辑操作，不展示初始化数据冒充真实数据。
- 充值配置弹窗增加高度限制和内部滚动。
- 测试通过拦截只读接口注入 503，验证导航、不可编辑状态、重试和移动端宽度。

## 下一阶段优先级与准入条件

| 优先级 | 工作项 | 验收标准／依赖 |
| --- | --- | --- |
| P0 | 企业数据隔离和权限边界 | 企业管理员只能访问本企业；需要后端权限专项测试 |
| P0 | 统一商品、权益与前台价格 | 唯一商品 ID／版本；前台报价与订单快照一致；需确认商业规则 |
| P0 | 真实支付、入账与任务扣费 | 回调验签、幂等、失败释放、到期控制；需支付与数据库环境 |
| P1 | 真实 Agent 创编 | 项目鉴权、报价、取消、差异预览、确认保存；需模型接口 |
| P1 | 草稿冲突与章节级版本 | 两端并行编辑不覆盖，统一旧章节编辑器与新工作台 |
| P1 | 所有管理配置复用保存保护 | 将本次套餐／充值的交互扩展到用户发放、模型及积分策略 |
| P2 | 灰度发布、回滚与经营指标 | 版本可回退；保存失败率、创作完成率、支付转化率有真实数据 |

## 边界

三轮完成的是前端交互小迭代，不代表三轮商业化上线。数据库仍未配置；单元测试的接口 mock 与浏览器注入错误不能替代真实服务联调。本地规则预览不是模型生成，前台收银台仍是模拟支付。没有推送 GitHub。
