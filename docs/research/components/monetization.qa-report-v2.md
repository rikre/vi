## 三、卡点清单与分级评审

> 分级标准：P1 阻塞发布（主流程不可用）/ P2 功能缺陷 / P3 体验或存量问题

### T-1（P1）团队版固定 3 席位，无法加购

| 项 | 内容 |
|----|------|
| 严重程度 | **P1**（4 人以上团队完全无法购买，主流程阻塞） |
| 现象 | 团队身份下三档套餐恒定 3 席位，无任何加购入口；「我有 4~5 个人」的场景无解 |
| 根因 | 定价模型只有「团队 = 个人 ×2」单一口径，无席位维度参数 |
| 解决方案 | 引入席位维度（业务拍板：**每加 1 席 = 个人版当前周期月价 × 1/2**）：基础 3 席 = 个人价 ×2；第 4–10 席按加席单价线性加收；积分池按 `×2 + 0.5×加席数` 线性扩容 |
| 修复位置 | `src/app/pricing/data.ts`（`TEAM_BASE_SEATS` / `TEAM_MAX_SEATS` / `extraSeatPrice()` / `teamCredits()`）、`src/app/pricing/page.tsx`（席位步进器 + 动态计价） |

**计价公式（口径统一，团队联调对齐用）**：

```
个人月价 P：月付 = monthlyOriginal；季付 = round(monthlyOriginal × 0.85)；年付 = yearlyMonthly
团队月价 = P × 2 + (席位数 − 3) × round(P × 0.5)      // 席位范围 3–10
积分池/月 = monthlyCredits × (2 + 0.5 × (席位数 − 3))
```

示例（专业版 · 年付 · 5 席）：`239×2 + 2×120 = 718/月` → 年付 **¥8,616**；积分池 `3920×3 = 11,760/月`。

> 文案口径说明：「单席位成本比个人版低约 33%」按基础 3 席年付测算（478÷3≈159 vs 239）；实际加席越多越便宜（5 席时约低 40%），对外文案取保守值。

### T-1-bug（P1）订阅回调漏传席位，收银台恒按 3 席计价

| 项 | 内容 |
|----|------|
| 严重程度 | **P1**（T-1 修复的实测验证环节发现；用户选 5 席下单，收银台仍按 3 席计价 → 错误订单金额） |
| 现象 | 卡片月价正确显示 5 席价（¥718/月），但收银台副标题「年付 · 3 席位」、金额按 3 席计算 |
| 根因 | `PlanCard` 订阅按钮 `onClick={() => onSubscribe(plan, cycle, identity)}` 漏传第 4 参 `seats`，`subscribe()` 落入默认值 `TEAM_BASE_SEATS` |
| 解决方案 | 补传 `seats`；连带修复卡片席位行引用死字段 `plan.seats`（数据从未赋值，恒不渲染）→ 改用步进器状态并追加「含加席 ×N」标注；清理 `data.ts` 中 `MemberPlan.seats?` 死字段 |
| 修复位置 | `src/app/pricing/page.tsx`（订阅回调 + 席位行）、`src/app/pricing/data.ts`（死字段清理） |

### T-3（P3，存量遗留）`use-film-assembly.test.ts` 联合类型错误

| 项 | 内容 |
|----|------|
| 严重程度 | P3（V1 报告遗留，`tsc --noEmit` 报错影响 CI 信号） |
| 根因 | `Project = ShortDramaProject \| ScriptProject` 联合类型，`scriptContent` 仅存在于前者；测试直接 `getProject(id)?.scriptContent` 未做类型收窄 |
| 解决方案 | 按同文件既有 `type === "short"` 收窄模式改写，并前置 `expect(stored?.type).toBe("short")` 防止收窄失败时断言静默通过（假阴性） |
| 修复位置 | `src/hooks/use-film-assembly.test.ts` |
