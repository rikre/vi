# 项目管理与创建模式走查报告

日期：2026-10-27  
基准：本地 Mock 数据、1440×900 浏览器、项目现有路由与存储。

## 1. 先区分两个维度

代码中没有“会模式”的正式定义。当前存在两套概念，不应混在同一个选择器里：

- **项目管理模式（新用户文案）**：Agent 模式（内部兼容值“剧本模式”）、人工模式（内部兼容值“自由模式”）、AI 重绘。
- **短剧创建方式**：与项目管理统一显示 Agent 模式、人工模式，不再使用“智能模式、全剧智能体、自主创作”。

如果“会模式”指“混合模式”，当前没有对应实现，需要产品确认后再新增，不能拿现有模式改名冒充。

## 2. 当前三种项目模式的创建要求

| 模式 | 当前必填 | 当前默认与保存 | 实测结果 |
| --- | --- | --- | --- |
| 剧本模式 | 项目名、剧本文件 | 默认 3 集；保存模式、文件名；TXT 保存文本内容 | 通过；创建后进入 `/comic/:id`，显示剧本相关工作台 |
| 自由模式 | 项目名、集数 | 默认 3 集，存储限制 1–200；生成对应数量空白剧集 | 通过；5 集正确生成，详情不显示剧本页签 |
| AI 重绘 | 项目名、原片文件 | 默认 3 集；保存模式和原片文件名 | 基础创建通过；进入原片→设定→分镜→视频四步工作台 |

共同规则：项目简介选填；项目名称 trim 后不能为空；项目列表创建成功后统一进入 `/comic/:id`。

## 3. 创建方式与跨页规则

| 入口 | 界面规则 | 实测问题 |
| --- | --- | --- |
| 首页智能模式 | 显示上传剧本区；项目名标星；可设置比例、打开风格库 | 项目名不校验；上传按钮实际只跳下一页；比例和风格不进入参数 |
| 首页人工模式 | 提示无需剧本，填写项目名即可 | URL 有 `name`、`mode=manual`，但下一页不读取 |
| `/project/new` 全剧智能体 | 默认选中；不强制上传剧本 | 与首页“智能模式”命名不同，未强制相同创建条件 |
| `/project/new` 自主创作 | 可切换剧本/分镜、风格、影调、比例 | 与首页“人工模式”命名不同；配置在保存时丢失 |

实测：首页填写“跨页参数走查”并选择人工模式，进入 `/project/new?action=short&name=...&mode=manual` 后，页面仍选中“全剧智能体”；最终保存为标题“做短剧”、模式“剧本模式”。

## 4. 主要问题与优先级

| 级别 | 问题 | 影响 | 建议 |
| --- | --- | --- | --- |
| P0 | 首页与 `/project/new` 的参数链断裂，名称、创建方式、比例、风格等未保存 | 用户选择没有生效，创建结果不可预期 | 先定义统一创建契约，再修查询参数解析、表单初始化与落库 |
| P1 | 智能/人工、全剧智能体/自主创作、剧本/自由模式混用 | 用户无法判断模式之间关系 | 统一用户文案；内部保留明确映射，不在同一层级混摆两个维度 |
| P1 | `/project/new` 只有原创想法有校验，其他动作可空表单提交 | 各入口创建标准不一致 | 所有创建动作补项目名和对应条件字段，使用共享校验 |
| P1 | 重绘上传 `mock-video.mp4`，工作台却显示另外 3 个预置视频 | 创建结果与输入不一致 | 新项目使用真实选择文件的 Mock 表现；无内容时显示空态，不展示他人资产 |
| P1 | 新自由项目显示预置创作动态；0/5 集未完成却出现“全部完成” | 进度与动态误导 | 新项目动态从空态开始；完成文案由实际剧集状态计算 |
| P1 | `/project/:id` 与 `/comic/:id` 的模式和操作不同 | 同一项目有两个行为版本 | 收敛到同一项目详情工作台，复用模式与操作配置 |
| P2 | 文件大小、格式主要依赖提示和 picker，拖放可绕过 | 边界行为不一致 | 选择文件和拖放共用扩展名、MIME、大小校验 |
| P2 | 创建成功路由、按钮文案和详情管理操作不统一 | 学习成本和回归成本增加 | 统一创建按钮、成功反馈、重命名/删除/归档操作 |

## 5. 推荐的统一创建标准（待确认模式命名后实施）

| 创建类型 | 项目名 | 条件字段 | 统一操作 |
| --- | --- | --- | --- |
| Agent 创作 | 必填 | 剧本文件必填，或明确提供“无剧本创作”分支 | 项目名→简介→模式→条件字段→配置→创建项目 |
| 人工创作 | 必填 | 计划集数必填，1–200 | 使用相同表单顺序与主按钮，不另起一套术语 |
| AI 重绘 | 必填 | 原片文件必填，格式和大小实时校验 | 主按钮仍为“创建项目”，辅助说明重绘结果 |

建议把“创建方式”映射到内部项目模式，而不是再增加一维并列选择。映射关系需要产品确认，例如人工模式是否等于自由模式，不能直接由开发者假定。

统一数据契约建议包含：`title / description / creationMethod / projectMode / episodes / sourceFile / ratio / style / tone / shortMode`。创建后在项目概览可回看这些配置。

## 6. 测试用例与结果

新增：`src/lib/project-creation-contract.test.ts`

可运行用例：

1. 剧本模式保存文件名和文本内容，并 trim 项目名。
2. 自由模式按 5 集创建未开始空白剧集。
3. AI 重绘保存原片文件名并生成默认结构。
4. 集数下限 0→1、上限 201→200。

待办契约：

- 首页项目名、创建方式、比例跨页保持。
- 创建方式与项目管理模式使用明确映射并完整落库。
- 风格、影调、剧本/分镜模式、比例创建后可回看。
- 同一项目在 `/project/:id` 与 `/comic/:id` 中模式与操作一致。

测试命令：

```bash
npm exec -- vitest run src/lib/project-creation-contract.test.ts src/lib/project-store.test.ts --maxWorkers=1
```

结果：**2 个测试文件通过，16 条通过，4 条待办**。首次默认多 worker 运行遇到既有 `broker.sock ECONNREFUSED`，改单 worker 后通过；这不是业务断言失败。

## 7. 推荐实施顺序

1. 先确认“会模式”含义，以及自动/手动与剧本/自由模式的映射。
2. 用共享 schema 统一必填、查询参数和落库字段。
3. 统一首页、`/project/new` 和项目列表弹窗的表单顺序、命名、按钮与反馈。
4. 清理新项目假动态、假原片与错误完成状态。
5. 最后合并两个项目详情工作台，再开启上述 4 条待办测试。
